# Featured course, workshop and bundle templates

Open any recorded course or live workshop in the admin course editor. Under Course Data, enable **Featured Page Layout** (the Arabic UI label translates to this) and save. Open the **Featured Page Layout** tab to customize the template. The control is also available when creating a course. For bundles, go to Offers and Bundles → Bundles, create/edit the bundle, enable Featured Page Layout and save. The bundle table has a Featured Page Layout link to `/admin/dashboard/commerce/bundles/[slug]/template`. Bundle pages stay under `/bundles/[slug]`; their default purchase actions target `/checkout/[slug]?kind=bundle`. Delivery and page design are independent: recorded courses remain at `/courses/[slug]`, live workshops remain at `/workshops/[slug]`. Disabled layouts use the shared standard details page. Drafts can be customized before publication.

The editor customizes the nine approved sections: introduction, client work, transformation, roadmap, reviews, instructor, guarantee, FAQ and closing call to action. Edit text and highlighted text parts, image/video URLs and image descriptions, links, captions, repeated records and accessible player labels. Sections can be hidden/reordered (the introduction stays present). Repeated items can be added, removed and moved; nested media/settings groups are collapsed to keep the form manageable. Show/hide the active-offer strip. It resolves the product’s current canonical commerce quote: the visible name is the saved active offer title, and the timer uses its fixed `ends_at`. There is no strip for disabled, scheduled, expired or absent offers; an active offer without an end date shows its name without a timer. The strip disappears at expiration without reloading. Demo viewer counts, rolling/local-storage urgency and prototype signup toasts are not rendered on featured product pages. Legacy stored timer/scarcity/signup fields remain readable for compatibility but are not editable or used as commercial urgency. Manage the name/target/dates under Offers and Bundles → Offers.

The same shared, login-aware Ta3llam navbar appears on featured courses and workshops; it is outside editable template content. The approved theme, responsive section styles, structural section IDs, icon geometry and reveal policy stay centrally controlled. This editor changes content/composition rather than accepting arbitrary HTML, scripts, CSS or new animation dependencies.

**حفظ التصميم** stores a per-course document; changes do not modify other workshops. Initial defaults derive from the workshop's own title, description, intro and curriculum, with the existing seven-day content retained as the approved starting template. Once saved, content is a snapshot: later course-data edits do not overwrite the custom template. Prices/payment eligibility continue to come from course/commerce records, not marketing text. Links are editable; administrators should keep purchase actions pointed at the appropriate checkout. **استعادة التصميم الافتراضي** resets the editor locally after confirmation; it takes effect only after saving.

## Persistence and access

`workshop_templates` retains its historical table name and has exclusive nullable course/bundle FKs, UUID primary key, per-target uniqueness, JSON document, optimistic revision and update timestamp. Admin APIs authenticate and authorize each request, enforce same-origin mutations, and reject stale revisions. RLS permits published featured content reads, keeps drafts private, and restricts writes to current admins for all existing courses and bundles. The table cascades with course/bundle deletion. Public bundle visibility requires enabled + featured and at least two published members. A narrow security-definer predicate checks those server-only bundle tables without exposing their configuration. Document validation rejects unsafe URLs, injected section attributes, arbitrary shapes, invalid timing values and excessive depth/size/items. Template requests alone have a bounded 128 KiB body cap; documents have a 96 KiB limit, leaving serialization headroom. Existing API limits remain in place.

Drive hero/reel links use a dedicated public marketing-media route that resolves only stored, validated clip identifiers for published featured courses, workshops and bundles; it accepts no arbitrary upstream URL. YouTube and existing direct/local sources continue through the shared custom player. This does not expose private lesson endpoints or download/rehost videos.
