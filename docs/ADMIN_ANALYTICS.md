# Admin Home analytics

`/admin/dashboard` is the Home page. User management is now `/admin/dashboard/users`; username-based user detail routes stay beneath that path. Courses, profile and settings retain their routes. Shared dashboard navigation supplies the Home, Users and Courses tabs.

Recharts 3.10.1 supplies the customized accessible SVG daily chart. It uses the platform's existing dark surfaces, red accent, Arabic typography and centralized theme roles. Shared chart/panel components accept data, labels and children; product components receive centralized content as props. The chart metric switches between signups and enrollments, compares the previous month, and provides an accessible daily table. Responsive layout is checked at 320, 390, 768 and 1440px.

`GET /api/admin/analytics` returns a validated aggregate snapshot, never raw student identities. The page and endpoint require current admin membership and an allowed account; responses are not cached. The private database definer is necessary to read Auth creation dates, explicitly checks live authority, uses an empty search path, and is exposed through an invoker wrapper with anonymous/public execute revoked. A created-date/course index supports enrollment aggregation. Local and hosted advisors report no issues.

Week/month boundaries use Africa/Cairo. Weeks start Monday. Comparison cards/course rankings use the same elapsed local duration in the previous period; month comparison caps at the previous month's end. The daily graph compares calendar-day buckets and stops at today. Missing calendar days in shorter previous months are null. Current admins and deleted accounts are excluded from student/enrollment counts. Historical figures describe current retained accounts/records, not an immutable audit history.

Course rankings are the five highest enrollment counts for week, month or all time, with stable slug tie-breaks and no zero-count rows. Learning summary counts current enrollments, distinct enrolled students and completed lesson records. Signup attribution uses recorded `acquisition_source` metadata when available; unsupported/missing values are unknown. No visitor-event tracker or visits-per-source count exists yet. Sources appear beneath every panel/metric. Revenue stays unavailable because no actual payment ledger exists; prices and enrollment counts are never treated as collected funds.
